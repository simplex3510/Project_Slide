
1. 유니티로 개발.
2. 개발 중 시스템이나 아키텍처의 확장성은 염두해 두되, 너무 함몰되지 말 것.
3. 그래픽은 픽셀 아트 스타일
4. 코드는 직관적이되, 너무 함축적으로 사용하지 말 것.
5. 어떤 기능을 함께 개발하거나 요청할 때, 한 번에 너무 많은 스크립트나 코드를 작성하여 사용자가 파악하기 어렵게 하지 말 것. (즉, 적당한 수준의 양만을 추가하거나 수정할 것)
6. 너무 혼자 앞서 나가서 코드를 개발하여 사용자가 전체적인 코드 파악이 어렵게 하지 말 것.
7. 개발 및 시스템 기획에서 추천되는 바가 있다면 적절히 언급할 것.
8. **새 스크립트(.cs) 분리 기준** — "입력/커맨드 단위"가 아니라 "독립적인 책임(상태 + 생명주기)을 가지는가"를 기준으로 판단할 것. 아래 조건에 해당하면 별도 컴포넌트로 분리하고, 아니면 기존 컴포넌트에 추가한다.
   - 자체 상태(state)를 가지는가 (예: 상태 머신, 여러 단계의 진행 상태)
   - 자체 생명주기 로직이 필요한가 (매 프레임 `Update`/`FixedUpdate`에서 독립적으로 실행되는 로직)
   - 다른 시스템이 이 상태를 참조/구독하는가
   - 책임의 이름을 한 단어로 명확히 지을 수 있는가

   위 조건에 해당하지 않는 단순 값 저장/노출(예: 입력값 하나를 프로퍼티로 노출하는 정도)은 기존 관련 스크립트에 추가하는 것으로 하고, 불필요하게 스크립트 수를 늘리지 않는다.
