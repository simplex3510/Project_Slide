## 0. 프로젝트 정체성

- **장르**: 로그라이트(Roguelite) 액션 어드벤처
  - 절차적 생성 던전 + 영구적 장비/기술 축적이라는 구조적 특징 때문에 "로그라이트"로 명확히 정의함
  - 다만 소울라이크식 고난이도·응징적 페널티·비장한 톤은 지향하지 않으며, Moonlighter식 관대한 진행 구조를 채택함
- **벤치마킹**
  - **레전드 오브 곡괭이**: 보스전 구성 및 시나리오 전반의 밈/패러디 활용 톤
  - **Moonlighter**: 탐험 및 아이템 제작 루프. 몬스터 처치 → 아이템 획득 → 제작법 획득/개발로 이어지는 순환 구조. 채광 기반 자원 채집 시스템, 광물 재련·보석 세공·마법부여(매개체 기반) 등 다층적 아이템 강화 체계
- **진행 구조 요약**: 사망 시 손실 발생 후 거점 귀환, 던전은 재입장 시 스펠렁키(Spelunky) 식으로 완전 재생성됨. "런(run)"이라는 명시적 단절 개념 없이, 하나의 연속된 모험 속에서 던전에 반복 진입하는 구조로 이해함

## 1. 게임 기본 정보

- **장르**: 로그라이트 액션 어드벤처 (§0 참고)
- **시점**: 탑뷰(Top-view)
- **이동**: WASD 상하좌우 이동 (게임 '아이작' 시리즈 참고)
- **공격**: 스킬 블록 조작으로 결정
- **전투 진행 방식**: 항상 **실시간**으로 진행됨. 스킬 블록 선택/드래그 중에도 게임은 일시정지되지 않으며, 캐릭터 이동/피격/적 행동이 계속됨

## 2. 전투 UI 구조 — 스킬 블록 슬롯

- 화면 우측에 세로형 스킬 블록 슬롯(bar) 존재
- 스킬 블록은 위 → 아래 방향으로 낙하하며 슬롯에 누적됨
- **슬롯 최대 용량**: 8개 (임시 수치, 추후 확정 예정)

### 블록 생성 규칙
- 스킬 종류별로 개별 생성 확률이 존재
- 해당 확률에 따라 랜덤하게 블록이 생성되어 낙하

---

## 3. 블록 사용 방식

| 조작 | 소비 블록 수 | 결과 |
|---|---|---|
| 탭(클릭) | 1개 | 해당 스킬 1단계 발동 |
| 드래그(다중 선택) | 최대 3개 | 선택 개수 = 강화 단계 (2개→2단계, 3개→3단계) |

### 드래그(체이닝) 조건
- **슬롯 내에서 서로 인접한 동일 종류 블록만** 체이닝(다중 선택) 가능
- 최대 3개까지 연속 선택 가능
- 드래그 도중(선택 중) 마우스 버튼을 떼지 않고 취소하면 → **스킬은 사용되지 않고 드래그만 취소됨**
- 체인 백트래킹: 포인터가 이전 블록으로 돌아오면 선택 리스트에서 해당 위치 이후를 잘라내는 방식
- 참고 레퍼런스: 크루세이더 퀘스트

---

## 4. 자원(마나, 가칭) 시스템

- 스킬 블록을 사용할 때마다 자원(마나, 가칭)이 생성/누적됨
- 자원이 특정 임계치에 도달하면 **전부 소모**하여 **특수 스킬(궁극기) 블록 1개** 생성
- 생성된 특수 스킬 블록은 **별도 슬롯이 아닌, 기존 낙하 슬롯에 동일하게 배치됨**

> 참고: 여기서의 "자원(마나)"는 전투 중 실시간으로 누적되는 스킬 발동 자원이며, §8의 필드 채집 자원(광물·보석·마법부여 매개체 등)과는 완전히 별개의 개념임. 혼동 방지를 위해 정식 명칭 확정 시 용어를 구분할 것.

## 5. 보유 스킬 목록

슬롯에 낙하하여 쌓이는 블록은 총 **4종류**로 구성됨.

| 스킬 종류 | 체이닝 여부 | 강화 단계 | 비고 |
|---|---|---|---|
| 일반 공격 (= 스킬1) | O | 1~3단계 | |
| 스킬2 | O | 1~3단계 | |
| 스킬3 | O | 1~3단계 | |
| 특수 스킬 | X (체이닝 불가) | 1단계 고정 | 강화는 추후 스킬트리/패시브 연계 시스템에서 별도 진행 예정 |

## 6. 스킬 사용 중 피격 판정 로직

### 6-1. 즉시 발동형 스킬 (모션 없음)
- "발동 중"이라는 시간 구간 자체가 존재하지 않음
- 사용 즉시 확정 처리 (취소 개념 미적용)

### 6-2. 모션이 존재하는 스킬
모션 내에 **"사용된 것으로 간주하는 기준 프레임(시점)"**을 하나 설정하여, 그 프레임을 기준으로 피격 시 처리가 갈림.

| 상황 | 블록 소멸 여부 | 피격 여부 | 결과 |
|---|---|---|---|
| 기준 프레임 **도달 전** 피격 | 소멸 안 됨 | 피격됨 | 스킬 발동 취소, 블록은 슬롯에 그대로 유지 → **즉시 재사용 가능** |
| 기준 프레임 **도달 후** (발동 중/완료) 피격 | 소멸됨 | 피격됨 | 스킬 정상 사용 처리, 블록 소모 + 피격 동시 적용 |

> 기준 프레임의 구체적인 수치는 추후 스킬별 모션 제작 단계에서 개별 지정. 현재 단계에서는 "구간 분리 원칙"만 확정.
> 참고 사례: 몬스터 헌터의 슈퍼아머(하이퍼아머) 개념과 구조적으로 유사.

> **적용 확장**: 동일한 기준 프레임 구조를 §8 필드 채집 판정에도 재사용함 (채집 모션 중 피격 시 채집 취소/확정 처리).

## 7. 캐릭터 방향 및 조준(공격 방향) 결정 로직

### 7-1. 캐릭터 바디 스프라이트 — 4방향 체계

| 방향 | 처리 방식 |
|---|---|
| 하(정면) | 별도 스프라이트 |
| 상(후면) | 별도 스프라이트 |
| 측면 | 별도 스프라이트 1벌 + `SpriteRenderer.flipX`로 좌/우 겸용 |
| 대각선 입력 | 가장 가까운 방향(상/하/측면)으로 스냅 처리 |

- `GetSnappedDirection(Vector2 facing) → enum {Down, Up, Side}` + `flipX` 여부로 매핑
- 대기·이동·피격·사망 등 **공통 모션**에 적용되는 기준

### 7-2. 공격/스킬 판정 및 이펙트 — 코드 기반 회전 하이브리드

- 근접 판정 히트박스, 투사체, VFX는 방향별 전용 애니메이션 없이 **공격 방향 벡터를 기준으로 코드에서 회전·배치**
- 스킬별 이펙트/판정 리소스는 **스킬당 1세트만** 제작, 방향 대응은 런타임 회전으로 커버
- 참고 사례: Enter the Gungeon, Nuclear Throne

### 7-3. 조준(공격 방향) 결정 로직 — 신규 확정

마우스는 스킬 블록 조작 전용으로 유지하기 위해, 조준(공격 방향)은 마우스 위치가 아닌 아래 우선순위로 결정함.

1. **직접 타겟팅(최우선)**: 좌클릭으로 적/대상을 직접 클릭하여 타겟팅. 단, 좌클릭이 스킬 블록 조작(§2, §3)과 동일한 입력이므로 **화면 영역(스크린 스페이스) 기준으로 완전히 분리**하여 처리함
   - 클릭 위치가 우측 스킬 블록 슬롯 영역 → 블록 조작으로 처리
   - 클릭 위치가 그 외 월드/전투 영역 → 해당 위치 레이캐스트 → 적 대상 지정
   - 플레이어는 두 영역을 명확히 구분하여 조작하는 것을 전제로 함
2. **간접 보정(소프트 어시스트)**: 직접 타겟팅으로 대상이 지정되지 않은 경우, 근접한 적 방향으로 조준이 자동으로 소폭 보정됨
3. **기본값**: 위 두 조건이 모두 해당하지 않을 경우, 최후 이동 방향(`FacingDirection`)이 조준 방향이 됨

> 미확정: 소프트 어시스트의 보정 강도(각도 범위, 스냅 세기) 수치는 프로토타입 단계에서 튜닝 예정.

## 8. 필드 자원 채집 시스템

- 던전/필드 맵 곳곳에 채집 가능한 자원 노드(광맥 등)가 배치됨
- 채집은 **전투 공간과 완전히 분리되지 않음** — 전투가 진행 중인 동일한 필드에서 선택적으로 채집 가능
- 채집 자체는 플레이어의 선택(리스크 감수) 사항이며, 강제되지 않음
- 채집 판정에는 §6의 기준 프레임 구조를 재사용: 채집 모션 중 피격 시 기준 프레임 이전이면 채집 취소(재시도 가능), 이후면 채집 확정 + 피격 적용

> 미확정: 채집 노드의 배치 방식(고정 위치 vs 절차적 배치), 노드별 재생(리스폰) 규칙.

## 9. 장비 강화 시스템

Moonlighter를 벤치마킹한 3계층 강화 체계. **순수 수치형 파워 스케일링**만 담당하며, 스킬의 질적 거동 변경(§10 참고)과는 명확히 분리됨.

| 강화 매개체 | 대상(재료) | 비고 |
|---|---|---|
| 재련 | 광물 | 무엇을 증강시키는지 미정 |
| 세공 | 보석 | 무엇을 증강시키는지 미정 |
| 마법부여 | 별도 매개체 | 무엇을 증강시키는지 미정 (마인크래프트 인챈트 참고) |

> 미확정: 각 강화 요소가 구체적으로 어떤 스탯/수치를 증강하는지는 추후 확정.

## 10. 스킬 시스템 (블록 속성/효과 변경)

- §9의 장비 강화와 별도의 축으로, **스킬트리/패시브를 통해 스킬 블록 자체의 속성이나 효과를 변경**하는 시스템
- 예: 체이닝 시 추가 효과 부여, 특수 스킬 생성 조건(마나 임계치 등) 변형 등 — 구체적 내용은 미정이며 개별 스킬 설계 단계에서 확정
- 특수 스킬(§5)의 강화 역시 이 시스템을 통해 진행 예정

## 11. 진행 구조 (로그라이트)

- **사망 시**: 자원 손실 발생 + 거점(마을/캠프 등)으로 귀환
- **던전 재입장**: 스펠렁키(Spelunky) 식으로 매번 완전히 새로 생성됨
- **"런" 개념 없음**: 명시적으로 성공/실패를 구분 짓는 런 단위가 아니라, 연속된 하나의 모험 속에서 던전에 반복적으로 다시 들어가는 구조로 취급함
- 영구적으로 축적되는 요소: 장비, 기술(스킬트리/패시브), 제작법 등 (§9, §10 연계)

> 미확정: 거점의 구체적 구조(상점/제작대/던전 진입 지점 등 허브 기능 구성)는 후속 세션에서 별도 논의 필요.

## 12. 톤 & 서사 방향

- **메인 시나리오**: 진지한 톤 유지
- **전역 톤**: 밈/패러디 기반 (레전드 오브 곡괭이 벤치마킹 — 네이밍, 대사, 보스 패턴 등에서 패러디 활용)
- **톤 전환 연출 장치**: 진지한 장면(보스 조우, 핵심 전환점)과 평상시 밈 톤을 구분 짓기 위한 장치들(BGM 급전환, 네이밍 컷인, 색보정 전환, 카메라 워크, UI 톤 분리)은 **현재 구현 우선순위에 포함하지 않음.** 향후 도입을 지속적으로 검토할 대상으로 기획 문서에만 아이디어 차원으로 남겨둠
